# データ分析ポートフォリオ

データ分析・機械学習の成果物をまとめたリポジトリ。講座の修了課題、学習用ノートブック、コンペ用テンプレートを収録。

---

## Why — このリポジトリの目的

分析の成果物は、放っておくと「動いたノートブック1枚」の形で散らばる。
書いた本人でも半年後には再現できず、他人には最初から読めない。

このリポジトリは、成果物を **あとから読める・もう一度動かせる** 形で残すために置いている。
そのために全プロジェクトで共通の構成を使い、次の3つを必ず備える。

- **何を解いたのか**（課題と、その課題が誰にとって意味を持つのか）
- **なぜその方法にしたのか**（選ばなかった方法と、選ばなかった理由を含む）
- **どうすれば再現できるのか**（環境の作り方と、実行するコマンド）

## Design Choice — 構成と、その理由

### 1つのリポジトリに複数のプロジェクトを入れる

分析プロジェクトごとにリポジトリを分けると、共通の書き方や設定を
そのつどコピーすることになり、少しずつ食い違っていく。1つにまとめて
**構成と設定を1か所で持つ**ほうが、増やすときの手間が小さい。

### プロジェクトの中は必ずこの形にする

```
<プロジェクト名>/
  README.md      課題・方法・結果・再現手順
  pyproject.toml このプロジェクトが必要とするライブラリ
  notebooks/     試行錯誤の記録（当時のまま残す）
  src/           再利用する部品（何度でも同じ結果が出る）
  tests/         部品の振る舞いを固定する検査
  data/          raw（取得したまま）と processed（加工後）
```

`notebooks/` と `src/` を分けているのが要点になる。ノートブックは
**考えた順番**の記録なので書き換えない。もう一度使いたい処理は
セルをコピーせず `src/` に切り出し、そちらに検査を付ける。

同じ処理が2か所にあると、片方だけ直したときに結果が食い違い、
しかもその食い違いは実行時に例外を出さない。数値だけが静かにずれる。

### 環境は uv で1つにまとめる

プロジェクトごとに仮想環境を切り替える運用は、切り替え忘れによる事故のもとになる。
uv のワークスペース機能を使い、各プロジェクトが必要なライブラリを自分で宣言したまま、
環境そのものは1つに保っている。

`uv.lock` はライブラリの版を固定した記録で、リポジトリに含めている。
これがあると、別の環境でも同じ版が入る。

## How-to — 動かし方

必要なもの：[uv](https://docs.astral.sh/uv/)（Python 自体も uv が用意する）

```sh
git clone https://github.com/nakatama225/data-science-portfolio.git
cd data-science-portfolio

uv sync              # 環境を作る
uv run pytest        # 全プロジェクトの検査を走らせる
uv run ruff check .  # 書き方の検査
```

個別のプロジェクトの動かし方は、各ディレクトリの README を参照。

## 新しいプロジェクトを追加するとき

`kaggle/_template/` に雛形がある。

```sh
cp -r kaggle/_template kaggle/<コンペ名>
```

追加したら、最上位の `pyproject.toml` の `[tool.uv.workspace] members` に
そのディレクトリを書き加える。
